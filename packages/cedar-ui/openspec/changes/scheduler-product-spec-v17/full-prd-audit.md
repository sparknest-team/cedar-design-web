## 基础组件重构边界

1. **通用布局单元**：先设计可选的事件组标识（候选名 `layoutGroupId`）。核心只按同列、同日期、时间连续的成员形成 unit，计算区间、重叠组、K、稳定 stackIndex、left/width/z-index；不读取出勤单或任务字段。单张普通 Event 自动成为一个 unit，休息作为普通只读 Event 参与布局。任务与出勤单关系仍由业务适配器提供。
2. **同一业务对象的多归属投影**：页面把人/设备两种展示块映射为各自稳定的视图 ID，并保留业务 ID 于 metadata。需要先验证受控更新、拖拽后联动与多块焦点；不能靠同一 Event ID 在同一周列中直接复制。
3. **视图结构**：日期轴和全天区应跟随同一横向坐标且在纵向滚动时固定；页面三列、Tree 搜索、待办分组、打卡和权限仍由业务工作台实现。
4. **业务保存**：技能、任务工时、来源、截止日、打卡、关单、逾期、角色权限和后端版本保留在 Demo/store 与保存钩子，不增加 Scheduler 状态枚举。

## 实施顺序与验收 Demo

1. **P0：数据模型与动态 Mock**。本周一为日期锚点，构造本周/下周/逾期/临期/已关闭/工作日轮休。一个出勤单映射多任务 Event；添加稳定业务 ID、归属色和组 ID，纯函数及契约测试覆盖拖动和多归属。
2. **P1：通用 layoutUnit**。实现并测试 FR-09 的 0.9W/K、宽度下限、间接重叠、首尾复用、整组焦点；默认单 Event 行为回归。
3. **P2：日历固定头部**。日期轴/全天区 sticky、今天高亮、周数/日期选择器、时间轴当前时间标签及三滚动区的浏览器验收。
4. **P3：PRD 三列工作台**。来源二层 Tree、搜索固定、对象色 checkbox、速加 toggle、独立待办二层树、人站同时勾选和两块联动；全部用 Cedar 内部组件及页面业务代码。
5. **P4：派单与详情闭环**。同设备任务勾选、空白新建、拖空白创建、拖已有单合并、技能硬拦截、时间/饱和度软提示、截止日蒙版、移出回池、打卡关联/手动补录、任务 hover 锚点与关单。
6. **P5：正式 FR 验收**。一个贯通 Demo 逐条执行 FR-01～FR-16；桌面浏览器实测三滚动条、窄屏横向滚动、密集重叠及任意今天日期的动态场景。旧专题 Demo 可保留作为 API 示例，不作为产品验收结论。

## 需要避免的误判

- 早期实施计划的勾选完成表示精简业务结果可演示，不等于完整 PRD 的任务级卡片、三列和联动体验通过。
- `overlapEventLimit` 可以留作组件通用能力，但产品 v1.7 工作台不得启用；月视图的「还有 N 项」是另一种视图，不受周视图 D25 限制。
- PRD 的修订记录有旧规则：以最终 FR 和 D17～D29 为准，拖动中的时间重叠/饱和度应软提示，不弹阻塞表单。
