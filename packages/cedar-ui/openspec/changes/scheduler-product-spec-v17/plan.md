# 任务日历 v1.7 早期精简实施记录

> 此记录基于此前不完整的摘录。完整 PRD 已于 2026-09-15 核对；正式验收差距和重构顺序见 [full-prd-audit.md](./full-prd-audit.md)。下方 [x] 仅表示早期精简 Demo 的实现，不表示 FR-01～FR-16 已通过产品验收。

## 设计约束

- Scheduler 不出现出勤单、任务、站长、休息、打卡、技能等业务概念。
- 优先使用现有 `event`、`editor`、`sidebar-extra`、`toolbar-extra` 和 `editor-request`。
- 新 API 必须能被至少两个不同业务场景解释，并且无法用现有插槽完成。
- 业务校验放在 `beforeChange`/`beforeTransaction` 和服务端；基础组件只提供变更上下文和错误出口。
- 接受少量交互调整，避免双层布局对象、业务状态机和专属页面结构进入核心。

## 已确定的合理口径

- `overlapEventLimit` 保留为基础组件可选能力；产品 v1.7 工作台不启用，所有堆叠层直接展示（D25）。
- 点击重叠卡片只置顶，保持原宽，失焦恢复。
- 使用当前百分比起点算法，不实现 D12 的另一套宽度公式。
- 驳回待补的红色竖线由业务通过外观字段设置，不增加状态枚举。
- 打卡记录进入业务详情，不在 Scheduler 增加 Tab 或数据类型。
- 早期 Demo 曾把一个出勤单映射为一个 Event；完整 FR-08/09 明确要求任务级日程块和通用 layoutUnit，正式验收需要重构该映射。
- 三列工作台属于页面 Demo，不属于 Scheduler 内部布局。

## P3：简化后的派单流程

- [x] 拖待办到空白格创建出勤单，沿用占位预览和自定义编辑器。
- [x] 合并已有出勤单改为“勾选待办 → 打开目标日程 → 加入任务”。
- [x] 业务编辑器校验执行人技能，自动求和标准工时并计算结束时间。
- [x] 移出任务在业务编辑器完成；最后一个任务移出时删除 Event。

## P5：早期基础 API 取舍（完整 PRD 下重新评估）

业务 Demo 完成后再审计缺口，按以下门槛决定是否进入组件：

| 候选能力               | 默认决定 | 进入核心的条件                                                           |
| ---------------------- | -------- | ------------------------------------------------------------------------ |
| `initialScrollMinute`  | 已实现   | 完整 24 小时轴下所有日历业务都需要初始定位                               |
| `can(action, context)` | 暂缓     | 至少两个业务需要动作级权限，readonly + 外部编辑器无法满足                |
| `accentColor`          | 已实现   | event 插槽无法稳定覆盖月、议程、时间线和拖拽镜像                         |
| event 作为 drop target | 不实现   | 点击合并无法接受，且有第二个通用拖入合并场景                             |
| layoutUnit/事件组      | 需重构   | 完整 FR-08/09 要求多个任务块共享横向几何；核心只处理通用组 ID 与时间布局 |
| 内置来源树/任务池      | 不实现   | 属于页面数据来源和业务信息架构                                           |
| 技能、打卡、状态枚举   | 不实现   | 明确属于业务领域                                                         |

## 验收顺序

1. 先完成业务适配器和静态工作台，验证信息是否足够。
2. 接通空白拖入、业务编辑和详情，验证完整任务闭环。
3. 让产品基于可操作 Demo 判断简化交互是否可接受。
4. 只对 Demo 实际暴露且无法绕过的通用缺口新增基础 API。
5. 最后补性能、键盘、触屏和后端权限/版本校验。

当前进度：后端权限与乐观并发版本校验已在业务工作台 Demo 中完成；键盘导航、Escape 手势取消和内置编辑器焦点恢复已完成。触屏日程拖动、缩放及空白拖选统一使用 350ms 长按，提前移动会取消排期手势，粗指针缩放热区已扩大。性能和外部 Popover/Dialog 的业务焦点管理继续作为专项验收。
