# Icon visual name-transition ownership

Both independent Icon implementations reproduce six controlled failures: stale name callback rollback, consumed callback unlocking a newer transition, inactive name scheduling, inactive/detached preference listener delivery, pending transition duration change, and iframe preference read from host window. Three normal deadline/reduced/disposal controls pass.

Use one normalized public transition value for CSS/JS (default0), invalidate and consume timer generations, suspend delays/listeners on KeepAlive deactivation, show latest name on activation without replay, and bind preference to actual span owner window with binding-generation guards. Registry/slot priority/spin/defaults and CSS variable layers remain unchanged; no new public API or token.

List source hints in this batch are method declaration/delegation, not native scroll execution; downstream VirtualList stays separate. Simulated media/iframe/timers do not certify native browser/OS or same-node document adoption.
