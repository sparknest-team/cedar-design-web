## 国际化

默认只注册并使用简体中文。内置语言包可从组件库根入口或 `@cedar-design/ui-vue/locale` 导入：

```typescript
import { addI18nMessages, cedarEnUS, getLocale, useLocale } from '@cedar-design/ui-vue'

addI18nMessages({ 'en-US': cedarEnUS })
useLocale('en-US')
console.log(getLocale()) // en-US
```

`cedarZhCN` 和 `cedarEnUS` 分别是简体中文、英文完整语言包。导入语言包不会自动注册或切换；`addI18nMessages` 默认保留已注册的同名语言，传入 `{ overwrite: true }` 可替换整个语言包，不会深度合并。`useLocale` 只接受已注册的语言；未知语言会提示并保持当前选择。`getLocale` 返回全局语言名称。

`ConfigProvider.locale` 可以为组件子树提供完整语言包，优先于全局选择；省略时沿 Provider 链继承，最终回退到全局语言。全局语言是模块单例，同一模块实例的多个应用和服务端请求共享，不应通过在 SSR 请求中修改全局语言来实现请求隔离。`getLocale` 不反映局部 Provider 的选择。

`useI18n` 虽然从根入口可见，但用于组件内部的 setup 上下文，不作为独立的应用国际化接口。它支持点路径和 `{0}` 等位置参数，缺失时返回键名。Cedar 的 `useLocale` 用于切换全局语言；Maple 同名的 `useLocale` 则创建独立实例，两者含义不同。
