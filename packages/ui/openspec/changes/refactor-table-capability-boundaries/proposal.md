# Cedar Table 能力边界重构

状态：2026-11-19 已开始实施；首批范围为兼容/体积基线以及列宽、冻结计算内核。详细结果见 [实施记录](./implementation.md)。

## 目标

保持 Cedar Table 已发布的功能、API、默认行为和现有使用方式，拆出可供移动端复用的列布局内核，并建立组件内部能力的按需依赖边界。用户原有的全量 Table 不需要修改 import、注册插件或迁移配置。

## 背景

`src/table/table.tsx` 直接装配分页、筛选、排序、选择、展开、拖拽、虚拟列表和滚动条；`table-th.tsx` 直接依赖筛选控件与浮层；`style/index.ts` 聚合这些依赖的样式。当前组件级子入口不足以保证按表格能力裁剪。Maple Table 则是原生插槽表格，不应因此依赖 Cedar 的桌面交互。

## 决策

- 既有 `Table` 永久承担完整功能入口职责；新增轻量使用方式必须主动选用。
- 分离列布局内核、Vue 布局生命周期、基础渲染、功能控制器和桌面 UI，静态组合功能，不做全局插件注册。
- 先在 Cedar 内部提取并保持行为，再提供轻量入口，最后按既有独立源码与同源检查规范接入 Maple。
- 先建立行为与发布产物基线，再以分阶段回归证明兼容；源码重排或体积下降都不能替代行为验证。

## 范围之外

本次实施不新增公共导出、不迁移 Maple、不改 React 仓库、不发布包。仅提取布局计算并保留旧函数适配，不顺便修改默认样式、数据处理语义、过滤交互、API 命名或浏览器/Vue 兼容下限。新移动端筛选界面另行设计。
